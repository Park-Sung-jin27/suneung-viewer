## 0) 검증 의무 사항 (redteam 우선 점검)

- [Pending] **데이터 schema 누락 항목 점검**: 아래 명세에 빠진 column / table 발견 시 차단

## 2) MVP 필수 기능 (D+30, 10개)

### M1. [Pending] `solving_log` 테이블 신설 (Supabase)

```sql
solving_log
├─ id (uuid, pk)
├─ user_id (fk → auth.users)
├─ set_id (text, e.g. "r2026a")
├─ question_id (int, e.g. 7)
├─ choice_selected (int, 1~5)
├─ is_correct (bool)
├─ pat (text, nullable, e.g. "R2") -- 학생이 틀린 선지의 pat
├─ created_at (timestamp)
└─ duration_ms (int, nullable) -- M3 의존
```

[Inference] 현재 `user_stats` RPC만 존재 추정. 패턴별 분포 집계 위해 raw log 테이블 필수.

**의존성**: 없음 (시작점)
**난이도**: 낮음
**구현 위치**: Supabase migration + frontend submit 시 insert

### M2. [Pending] `parent_email` 등록 UI

```
QuizPanel 또는 마이페이지
└─ "학부모 리포트 받을 이메일" input
   └─ Supabase user_profiles.parent_email 저장
```

[Inference] 학생 본인 이메일과 학부모 이메일 분리 필수. 89,000원 결제자(학부모)와 사용자(학생) 분리는 한국 입시 시장 표준.

**의존성**: 없음
**난이도**: 낮음
**개인정보 동의**: 등록 시 동의 체크박스 필수 ([Pending] redteam 점검)

### M3. [Pending] 풀이 시간 측정 (frontend timestamp)

- 문제 view 진입 시 `start_ts` 기록
- 정답 확인 클릭 시 `end_ts` 기록
- `duration_ms = end_ts - start_ts` → M1 column에 저장
- 60초 초과 시 "이탈"로 간주, NULL 저장

[Inference] 등급 추정 정확도 향상 + "빠르게 푸는 학생 vs 신중한 학생" 진단에 사용.

**의존성**: M1
**난이도**: 낮음

### M4. [Pending] 패턴 분포 집계 RPC

```sql
get_pattern_distribution(user_id, period_start, period_end)
→ {
    "R1": {count: 12, pct: 12.0},
    "R2": {count: 38, pct: 38.0},
    "R3": {count: 28, pct: 28.0},
    "R4": {count: 15, pct: 15.0},
    "V":  {count:  5, pct:  5.0},
    "L":  {count:  2, pct:  2.0}
  }
```

[Inference] 리포트 페이지 4(오답 패턴 진단)의 핵심 데이터. **리포트 차별점 90%가 이 RPC에 의존.**

**의존성**: M1
**난이도**: 중

### M5. [Pending] 분야별 정답률 집계 RPC

```sql
get_section_accuracy(user_id, period_start, period_end)
→ {
    "독서": {correct: 45, total: 60, pct: 75.0},
    "문학": {correct: 38, total: 50, pct: 76.0},
    "화작": ..., "언매": ...
  }
```

**의존성**: M1
**난이도**: 중

### M6. [Pending] AI 진단 코멘트 생성 module

```
input: 학생 데이터 (M4 + M5 결과 + 가장 자주 틀린 문제 top 3)
       + few-shot examples (김과외 실제 코멘트 10개)
       + 강사 톤 system prompt
↓
Anthropic API call (Claude Sonnet)
↓
output: 페이지 4 진단 코멘트 텍스트 (300~500자)
```

**의존성**: M4, M5
**난이도**: 중-고 (프롬프트 engineering이 결정)
**비용**: 학생 1명당 약 100원 ([Inference] Sonnet input ~1k token + output ~500 token 기준)

[Pending] **redteam 점검 필수**: 
- few-shot example 10개 중 학생 개인정보(이름·구체 점수)를 제거했는가?
- system prompt에 "학생 데이터 외 추측 금지" 명시되어 있는가?
- output에 학생이 풀지 않은 문제 인용 금지 가드 있는가?

### M7. [Pending] PDF 템플릿 (HTML, 5장)

```
├─ Page 1: Executive Summary

├─ Page 4: 등급 추정 + 추세
```

**의존성**: M4, M5, M6
**난이도**: 중

### M8. [Pending] 차트 렌더링 (Chart.js or recharts → SVG)

- 막대그래프 (분야별 정답률)

**의존성**: M7

### M9. [Pending] PDF 변환 pipeline


[Pending] redteam 점검: Puppeteer vs React-PDF 선택 — chart 품질·layout 자유도 trade-off

## 5) 의존성 다이어그램

```
[데이터 수집 layer]
  M1 (solving_log) ─────┬─── M3 (duration)
                        ├─── P1 (cs_click)
                        ├─── P2 (qa_log)
                        ├─── P3 (vocab_progress)
                        └─── F4 (재시도)
  
[집계 layer]
  M1 ──→ M4 (패턴 분포 RPC)
       └→ M5 (정답률 RPC)
       └→ P4 (추세 RPC)
       └→ P5 (등급 시계열)
       └→ F1 (peer comparison)

[생성 layer]
  M4 + M5 ──→ M6 (AI 진단) ──→ M7 (HTML 템플릿)
                              └→ M8 (차트)
                              └→ M9 (PDF 변환)

[발송 layer]
  M9 + M2 ──→ M10 (이메일) ──→ F3 (카톡)
  
[자동화 layer]
  P6 (cron) + P7 (필터) + P8 (검수 queue)
  
[기타]
  F2 (학부모 dashboard) — 독립 (M2만 의존)
```

## 응답 끝 — 3가지

### 1) 지금 당장 해야 할 것
1. **본 spec을 redteam(GPT)에 그대로 전달**: 22개 기능 list + 의존성 + [확인 필요] 항목 점검 의뢰. 특히 0번(검증 의무 사항)과 6번(빠진 가능성) 집중 검증.
2. **M6 (AI 진단 코멘트) prototype 우선**: 다른 기능 시작 전. 김과외 실제 코멘트 10개를 텍스트 파일로 정리 → few-shot 프롬프트 작성 → output 품질이 89,000원을 정당화하는 수준인지 직접 검증.
3. **M9 (PDF 변환) Vercel 한도 검증**: Puppeteer가 Vercel serverless에서 동작하는지 prototype 1개로 확인. 안 되면 React-PDF 또는 Edge Functions 마이그 결정.

### 2) 하지 말아야 할 것
1. **MVP 10개 동시 작업 금지**: 의존성 순서대로 직렬 진행. M1 → M4·M5 → M6 → M7~M9 → M10. 병렬 작업은 burnout + 통합 오류 risk.
2. **F1 (peer comparison) MVP 진입 금지**: 데이터 30명 이상 필요. 사용자 5명 단계에서 띄우면 통계 노이즈로 신뢰 무너짐.
3. **카톡 알림톡 MVP 진입 금지**: 알림톡 service 가입·승인 절차 별도 (1~2주 소요). MVP 발송은 이메일만.
4. **인간 검수 단계 생략 금지**: M6 코멘트 첫 50건은 본인이 직접 확인. AI generic 코멘트 발송 시 89,000원 perception 무너짐 + 환불 분쟁 risk.

### 3) 가장 큰 리스크
**"M6 (AI 진단 코멘트)의 품질이 generic하게 나와서, redteam 검증·인간 검수 두 단계로도 막지 못하고 베타 학부모에게 발송 → '이 코멘트는 ChatGPT가 5초만에 쓴 거잖아' 인식 → 첫 베타 50명 churn → 재진입 어려움"**

→ **방어 3중**:
1. **few-shot 강제**: 김과외 실제 코멘트 10개 미작성 상태에서는 M6 코드 작성 자체를 시작하지 말 것. 프롬프트 example이 코멘트 품질의 80%.
2. **검수 queue 발송 lock**: P8 (인간 검수 queue)이 동작하기 전까지 M6 → M10 자동 pipeline lock. P8을 MVP에 포함하는 안 [Pending] 검토.
3. **베타 학부모 인터뷰**: 첫 5명 발송 후 학부모 직접 인터뷰 — "이 리포트 89,000원 가치인가?" 5명 중 3명 이상 긍정 시에만 다음 50명 발송.
