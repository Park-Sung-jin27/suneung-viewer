# [백로그] `quality_gate.mjs:1757` — verse/`\n` 눈가림

> 발주 2026-08-24 지시로 **기록만** 한다. 개선은 별도 발주 사항. 지금 손대지 않는다.

## 무엇인가

`C_anchor_exact_fail` 축은 `sent.t` 에 줄바꿈이 있으면 그냥 통과시킨다.

```js
// pipeline/quality_gate.mjs:1757
if (ms.sentType === "verse" || region.includes("\n")) continue;   // (d) verse / 줄바꿈 → 운문 정상
```

의도는 「운문은 줄바꿈이 정상이니 공백 차이를 문제 삼지 말자」이다. 그런데 조건이
`sentType === "verse"` **또는** `region.includes("\n")` 이라, **산문이라도 그 구간에
줄바꿈이 하나 있으면 축이 눈을 감는다.**

## 실증

재추출 43세트의 `sents.t` 는 조판 줄바꿈을 49.5% 안고 있었다. 그동안 이 축은 **1건**만
잡았다. 줄바꿈을 정리하자 같은 데이터에서 **20건**이 드러났고, 건별로 보니

- 9곳은 본문의 진짜 공백 오류 (`서대주노비` · `봉건적성장과` · `있었다고주장하였다` 등)
- 4곳은 인용문 쪽 오류

둘 다 **줄바꿈이 있는 동안에는 한 건도 보이지 않았다.**

## 왜 기존 데이터에도 해당하는가

| 필드 | 기존 353세트 줄바꿈 보유 |
|---|--:|
| `sents.t` | 110/10,874 (1.0%) |
| `questions.bogi` | 131/1,312 (10.0%) |
| `choices.t` | 139/6,840 (2.0%) |

기존 데이터에도 `\n` 낀 문장이 110개 있고, **그 문장들은 이 축의 검사를 받은 적이 없다.**
비율은 낮지만 축이 원리적으로 못 보는 구간이라 「0건이니 문제없다」고 말할 수 없다.

## 개선 방향 (후보 — 판정하지 않음)

1. 조건을 `sentType === "verse"` 만으로 좁히고, 줄바꿈은 공백과 동등하게 보고 비교
2. 줄바꿈이 있는 구간은 통과시키되 **`W_` 경고로 남겨** 눈감은 사실을 기록
3. 산문 `sentType` 에는 줄바꿈 예외를 아예 적용하지 않음

어느 쪽이든 기존 데이터에서 신규 위반이 나올 수 있으므로, **적용 전에 기존 353세트
대상 영향 측정이 선행**되어야 한다.
