## 3. 세트 id 충돌 검사 — 실측 완료

`yearKey::setId` 복합키 기준으로 **기존 353세트 ↔ 신규 41세트 충돌 0건**.

| 회차 | 신규 id | 기존 id |
|---|---|---|
| 2015_9월B | `r20159c` `r20159d` `l20159a`~`l20159d` | `r20159a` `r20159b` |
| 2018_9월 | `r20189c` `l20189a`~`l20189d` | `r20189a` `r20189b` |
| 2016_6월B | `l20166b`~`l20166e` | `l20166a` 외 독서 4 |
| 2020_9월 | `l20209a`~`l20209d` | 독서 3 |
| … (나머지 14회차 동일 방식) | | |

⚠ 회차가 다르면 같은 setId 가 존재한다(예: `l20149d` 가 2014_9월A·B 양쪽).
이는 **기존 데이터의 기존 관행**이고 `RELEASE_KEYS` 가 `yearKey::setId` 복합키라 문제가 없다.
**setId 개명은 영구 금지**이므로 신규 id 도 그대로 둔다.

## 4. 병합 방식

각 회차의 `reading` / `literature` 배열에 신규 세트를 **append** 한다.
- 배열 안 순서는 기존 데이터가 문항 번호 순이 아니다(예: 2015_6월B 기존 `r20156e, r20156b, …`).
  따라서 **정렬을 새로 하지 않는다** — 정렬은 화면 쪽 책임이고, 여기서 바꾸면 기존 순서가 흔들린다.
- 기존 세트는 **한 글자도 건드리지 않는다.**
- 쓰기는 `fs.writeFileSync` + `JSON.stringify(data)` (minified 재직렬화, 최소 diff · §13⑪).
