## A. 2014 3세트 — 스캔 PDF

`_done/2014수능A` · `_done/2014수능B` 시험지는 문장 검색이 **전 지면 0건**이고
`[A]`~`[F]` 라벨 글리프도 **전 지면 0개**다. 텍스트층이 없는 스캔본이다.

벡터선은 뽑히지만 **어느 문장이 어디 있는지 알 수 없어** 구간을 sentId 로 옮길 수 없다.
OCR 로 좌표를 만들면 「원문 없이 생성」(§13⑬)에 해당하므로 하지 않는다.

→ **대표 판단 필요.** 선택지: ⓐ 텍스트층 있는 원본 PDF 확보 ⓑ 보류하고 대장에 기록.

## C. 도구가 놓친 3건 — 원인 확정

### `r20169g` 15면 (x=454.6)
```
[A] 꺾쇠 162.0 / 332.2   라벨 [A] y=242.4  (구간 중앙 247.1 ✅)
[B] 꺾쇠 621.0 / 754.4   라벨 [B] y=684.4  (구간 중앙 687.7 ✅)
   세로선 621.0~682.0 + 696.2~754.4 — 라벨 자리에서 끊김
```
브래킷이 명확히 존재한다. `bracket_map_v2` 가 놓친 것은 단 판별에서 걸러진 탓으로 보인다.

### `l20229b [B]` 9면 우단 (x=717.0)
```
[A] 꺾쇠 744.4 / 764.8   라벨 y=750.0
[B] 꺾쇠 854.7 / 875.1   라벨 y=860.3
   세로선 744.4~747.5 (3.1pt)
```
★ **원인 확정**: 도구가 `세로선 길이 < 8pt` 를 버린다. 라벨이 구간 대부분을 차지하는
**1행짜리 구간**은 세로선이 3pt 남짓이라 통째로 탈락한다.

단, 9면 우단에 `[A]` 가 또 있다. 8면 좌단의 `[A]`(765.8/839.5, D-110-2 에서 s26~s28 정박)와
별개다 — 9면 우단은 다른 세트일 가능성이 높다. **정박 전 세트 귀속부터 확인해야 한다.**

### `r20176a` 7면
라벨 `[A]` x0=107.7 y=906.1 · `[B]` x0=107.7 y=1002.1 은 있으나
그 x 대역(95~125)에 세로선이 없다. x=436.6 의 18.4pt 조각들은 단 구분선이다.
**구간 표시 형태가 다를 수 있다** — 지면 렌더로 눈 확인이 필요하다.

## 도구 한계 2가지 (이번에 드러남)

1. **세로선 최소 길이 8pt** — 1행 구간을 버린다(`l20229b [B]` 실측 3.1pt)
2. **꺾쇠 가로획 길이 4~20pt** — 표 구분선(26pt)은 잘 걸러지지만,
   폭이 다른 조판을 만나면 놓칠 수 있다

둘 다 고치면 표 테두리·단 구분선이 섞일 위험이 커진다. **임계를 바꾸기 전에
확정 세트로 재검증하는 절차를 반드시 거친다**(합격선 방식 유지).
