## 결론

> **현행 파이프라인은 결함을 재생산한다 — 단 "추출 층"에 한정한 판정이다.**

같은 예시문항 PDF에서 선지 수 이상, 문항 중복, `<보기>` 분리 실패가 나왔고, 이는 기존
데이터에서 확정한 결함 유형(선지 뭉침·`<보기>` 내용 이탈·마커 미정박)과 같은 계열이다.

**마커 층·게이트 층은 측정하지 못했다.** LLM 0 규율로 step2(구조화)·step3(해설 생성)을
실행할 수 없어 `all_data` 형식이 만들어지지 않았고, `marker_audit` 4축과 게이트 4종은
모두 그 형식을 입력으로 받는다. 이 두 층에 대해서는 **판단이 서지 않는다.**

같은 PDF, 같은 `parseQuestionBlocks`, 리더만 교체:

*(위 32/36 은 cd 수정 전 값. cd 수정 후 pdf-parse 는 33/36)*

### 원인

**2단을 단(column) 단위로 분리하느냐, 시각적 행 단위로 병합하느냐.**

`-layout` 실측 표본:
```
… 돼지가 살았다지요 반들거리는 검은 털에 날렵한 주둥이  ⇢  ④ '큰 거미 없어진 곳'은 …
… ㉠ 컴퓨터와 같은 완전히 물리적인 체계는 정신을 가질   ⇢  ② ㉡의 '제 힘으로'라는 …
```
좌단 지문과 우단 선지가 물리적으로 같은 줄에 있다. 그 결과 문항 헤더가 줄 첫머리에 오지
못해 **블록이 36 → 19 로 반토막**나고, 남은 블록도 선지 경계가 무너진다(6·7·9·11개).

→ `readerSanity()` 로 코드에 고정. 임계 50‰ (두 실측값 사이). `-layout` 계열 텍스트가
들어오면 추출 단계에서 중단한다.

## 기존 LIVE 데이터 영향 — 0건 (단서 있음)

위 혼입 패턴을 LIVE 353세트에 적용한 결과 **0건 / 0세트**.

이 0건은 **양성 4/4 · 오탐 0/3 회귀를 통과한 뒤의 수치**다. 1차 매처는 4패턴 중 3개가
죽은 채로 0건을 냈다(§13⑮(7) 재실증).

단 이 매처는 **"문장 안에 다른 단 조각이 남아 있는" 형태만** 본다. 혼입 후 조각이 잘려
나간 손상은 구조적으로 못 보므로, **0건이 "2단 조판 영향 없음"을 뜻하지는 않는다.**
