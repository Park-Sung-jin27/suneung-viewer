# 결함 표지 · 결론줄 전수 대장 (D-133 ④)

> 생성: `node pipeline/release_diag.mjs "<yearKey>::<setId>"` 의 ⑫⑬ 축과 같은 규칙으로 전수 스캔.
> **지금 수리하지 않는다** — 배치 C/D 에서 처리한다(D-133 ④ 판정).

## 무엇을 세는가

| 키 | 성격 | 처리 |
|---|---|---|
| `_pat_error` | pat 이 비어 있다는 **결함 표지** | 수리 후 제거 |
| `_ok_analysis_mismatch` | ok 와 결론 기호가 어긋난다는 **결함 표지** | 수리 후 제거 |
| `_discriminative_validation` | **일상 산출물** — LIVE 세트 포함 526건이 갖고 있다 | 지우지 않는다. `passed` 만 갱신 |

`_discriminative_validation` 을 결함으로 세면 LIVE 14세트가 통째로 걸린다. 표지가 아니다.

## 순서 규칙 (D-133 ② 채택)

**수리가 먼저, 표지 제거가 나중이다.** 표지를 먼저 지우면 결함이 남은 채 게이트만 조용해진다.
`pipeline/defect_marker_clear.mjs` 는 지우기 전에 그 표지가 가리키던 결함이 실제로 사라졌는지
스스로 확인하고, 확인이 안 되면 아무것도 지우지 않는다.

## 처리 계획

- 결함 표지 9세트는 **전부 비노출**이다. 배치 C(2017~2018) 와 배치 D(2014~2016) 에 걸려 있고,
  `r20199c` 만 배치 B(2019~2020) 다. 각 배치 진단 때 함께 처리한다.
- ⑬ 10건도 전부 비노출이다. `r20169b Q24#5` 는 결론 기호가 **아예 없는** 유일한 건이다.
- `l20166b`(2016_6월A)는 ⑬ 에, `l20166b`(2016_6월B)는 ⑫ 에 걸려 있다 —
  **같은 setId 가 다른 회차에 있는 경우**라 복합 키로만 구분된다(D-113 ①).

## ⑬ 축이 처음에 76건을 잡았던 이유 — 오탐이었다

해설 결론 형식이 세트마다 다르다:

```
A형   … 분석 …
      ❌ 지문과 어긋나는 부적절한 진술          ← 결론이 마지막 줄

B형   … 분석 …
      ❌ 왜 틀렸나                              ← 결론이 헤더 줄
      <설명 여러 줄>
```

처음에는 「마지막 줄」만 봐서 B형 세트(2019_6월·2024수능 등 LIVE 19세트)를 통째로 오탐했다.
**마지막으로 판정 기호가 등장하는 줄**을 결론줄로 보도록 고쳐 76건 → 10건이 됐고, LIVE 는 0 이 됐다.
