# CS_SPAN_UNRESOLVED 원인 진단 + 분리 게이트 재판정 (2026-08-24)

> 발주: 「진단 먼저, 수리는 보고 후」 — 이 문서는 **진단·재판정만** 담는다. 데이터는 손대지 않았다.

## 1. 결론 세 줄

1. `CS_SPAN_UNRESOLVED` 는 **축 오탐이 아니다.** 기존 353세트에 같은 잣대를 대면 span 5,323개 중 실패 **0건**.
2. 원인은 **재추출 본문(`sents.t`)에 PDF 조판 줄바꿈이 그대로 남은 것** — 신규 1,965문장 중 **973개(49.5%)**. 기존은 110개(1.0%).
3. 파일럿 기준 64건은 19회차 전체로 **695건**. 그중 **596건(85.8%)이 표기 차이**, **99건(14.2%)만 진짜 텍스트 불일치**.

## 3. 실패 695건 — 무엇 때문에 못 찾는가

게이트는 `sent.t.indexOf(span.text)` **완전 일치**를 요구한다. 정규화를 한 겹씩 벗기며 재측정:

| 정규화 | 해소(누적) | 증분 |
|---|--:|--:|
| 공백 전면 무시 | 461 | +461 |
| + 따옴표 통일(`“”` ↔ `'`) | 483 | +22 |
| + 마커 제거(`㉠` `ⓐ` `[A]`) | 500 | +17 |
| + 한자 괄호·각주표 `*` 제거 | 596 | +96 |
| **남는 진짜 불일치** | **99** | (14.2%) |

**공백 하나로 461건이 풀린다.** 줄바꿈이 두 가지로 섞여 있어 「공백 치환」도 「제거」도 단독으로는 안 되고, 공백을 **전면 무시**해야 맞는다.

```
어절 경계에서 끊김 → 공백 필요 :  "종로의 공원 건너편 응달에⏎앉아서"
어절 중간에서 끊김 → 제거 필요 :  "아무쪼록 깨끗이 풀어 주⏎시기를"
```

한글은 하이픈 없이 단어 중간에서 잘리므로, 조판 줄바꿈은 **공백도 아니고 문자도 아니다.**

- 재추출 973개 줄바꿈 문장 중 **901개가 한글 단어 중간 절단**
- 기존 110개 중 69개 (절대량이 1/9)

### 남는 99건의 성격

- **98건 = step4 가 원문을 그대로 인용하지 않음.** 마커를 빼고(`㉢ 성진이` → `성진이`), 앞뒤를 `...` 로 자르고, 큰따옴표를 작은따옴표로 바꿔 「읽기 좋은 인용」을 만들었다.
- **1건만** span 이 다른 문장에 실재(`sent_id` 오귀속).

## 4. 이것은 CS_SPAN 만의 문제가 아니다 `[Inference]`

`sents.t` 의 줄바꿈은 화면에 그대로 렌더된다. 병합하면 학생 화면에서 문장 중간이 끊겨 보이고, 본문 검색·형광펜도 같은 이유로 어긋난다. **병합 전에 본문 정리가 선행되어야 한다** — 수리 방침은 대표 결정 사항.

## 5. 분리 게이트 재판정 — 「기존 변동 0」이 산술로 닫혔다

`merge_reextract.mjs` 판정부를 **loc 파싱 폐기 → 기존만/신규만/병합본 3벌 직접 비교**로 교체했다.

```
기존만  세트 353 · 선지 6840 → CRITICAL  487
신규만  세트  43 · 선지  780 → CRITICAL  798
병합본  세트 396 · 선지 7620 → CRITICAL 1285

기존 변동 = 1285 − 487 − 798 = 0  ✅
신규 CRITICAL 위반율 = 798/780 = 102.3%  (기존 7.1% · 정지선 15%) 🔴 정지·원복
```

판정기가 3연속 틀렸던 값(130.5% → 3.3% → 0.0%)의 **진실은 102.3%** 다. 파싱이 없으므로 이제 틀릴 여지가 없다.
※ 전체 issues 기준 상호작용은 36건(WARN 축). 판정 기준은 CRITICAL 로 고정(D-93 후속 ④)이라 통과.

### setId 재부여는 하지 않았다 — 처방이 틀렸다 `[Confirmed]`

발주의 「충돌 13건 전역 유일 재부여」는 **실행하지 않았다.** 근거:

- `setId` 는 **애초에 회차 안에서만 유일하도록 설계**됐다. `src/dataLoader.js:91` — 「yearKey::setId composite key 단독 path → A/B form 분리 노출 정합」
- **기존 353세트도 29종이 회차 간 중복**이다(`r20146a` 가 2014_6월A·B 양쪽 등). 신규 13건은 같은 규칙을 지킨 것뿐이다.
- **회차 내 중복은 0회차·0건** — 데이터 구조상 위험 없음
- 신규만 전역 유일로 바꾸면 기존과 명명 규칙이 어긋나고, 기존 29종 충돌은 그대로라 **귀속 문제는 해결되지 않는다**

진짜 원인은 데이터가 아니라 **게이트 리포트 `loc` 에 yearKey 가 없는 것**이었고, 분리 게이트가 파싱 자체를 없애 이 문제를 소멸시켰다.
