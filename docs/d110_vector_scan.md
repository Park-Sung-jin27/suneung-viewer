# D-110 벡터 전수 스캔 — 중간 산출물

> 생성: `python pipeline/bracket_autoscan.py <setId> ...`
> 대상: C-7 불일치 18라벨 + 마커 공백 LIVE 11라벨 (23세트)

## 도구 신뢰도 — 읽기 전에 반드시 볼 것

`bracket_autoscan.py` 는 **브래킷 위치(꺾쇠 좌표) 탐지는 정확**하다.
D-109 에서 손으로 확정한 6건(l20276d 3구간 · l20226b 2구간 · l2021a [A] · r20226b [A])을
전부 자동 재현했다.

그러나 **행 → sentId 매핑은 신뢰할 수 없다.** 실측 반례:

- `r20209a [A]` — 브래킷 419.5/587.0 은 손 판독과 같은데, 매핑이 `s10~s14` 로 나왔다.
  화면값 시작 `s38` 은 그 브래킷 **안**(y0 452.8)에 있다. 즉 매핑이 틀렸다.
- `l2021a [B]` — 손 확정 `s55~s67`, 도구 `s55~s65`.

원인은 PDF 조판 줄이 문장 경계와 다르고, 짧은 줄·반복 어구에서 `sent_of` 가
엉뚱한 문장을 집기 때문이다. **따라서 「다름」·「없던 구간」 판정은 이 문서만으로 확정하지 않는다.**
「같음」은 화면값과 벡터 두 경로가 일치한 것이라 상대적으로 강하다.
