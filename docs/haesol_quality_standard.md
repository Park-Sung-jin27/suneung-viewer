## 1. 인용 규약 — 📌 근거 블록과 🔍 해설 블록

> **📌 근거 블록의 인용은 지문·`<보기>`의 연속 문자열 그대로 쓴다.
> 요약·재구성·설명 괄호를 넣지 않는다. 보충 설명은 🔍 블록에 쓴다.
> 원문에 있는 마커·각주·위첨자는 그대로 두고 임의로 지우지 않는다.
> 🔍 블록은 설명이므로 원문 인용 의무가 없다.**

### 왜 이렇게 나누는가

형광펜 근거 연결이 제품의 핵심이다. 학생이 해설의 📌 근거를 누르면 지문의 해당 구간이 형광펜으로 표시된다. 그 연결은 **문자열이 정확히 일치할 때만** 성립한다. 그래서 📌 블록의 정확성이 곧 제품의 정확성이다.

🔍 블록은 설명이므로 같은 제약을 받지 않는다. 풀어 쓰고, 비교하고, 요약해도 된다.

### 📌 블록에서 하면 안 되는 것

| 유형 | 예 |
|---|---|
| 요약 | 원문 「명시적인 인센티브 계약이 성과를 늘리기 위한 근로자의 노력을 더욱 늘어나게 하는 효과만 생각한다면」 → 📌 「노력 증가 효과만 생각할 때」 |
| 재구성 | 원문 「단면이 정사각형인 물체 ㉮와 직각이등변 삼각형인 물체 ㉯가 연결된」 → 📌 「물체 ㉮(정사각형)와 ㉯(직각이등변삼각형)가 연결」 |
| 설명 괄호 | 원문 「그것이 관측되지 않았다」 → 📌 「그것(직경 10∼20 nm의 먼지 미립자)이 관측되지 않았다」 |
| 문장 결합 | 서로 떨어진 두 문장을 하나의 따옴표 안에 이어 붙이는 것 |
| 마커·각주 삭제 | 원문 「390∼780 nm* 정도인데」 → 📌 「390∼780 nm 정도인데」 |

### 📌 블록에서 해도 되는 것

- 말줄임표(`...`)로 중간을 생략하기 — 단 **생략 앞뒤 조각은 각각 원문 그대로**여야 한다
- 원문이 여러 행인 운문을 행별로 `📌` 줄을 나눠 인용하기
- 원문에 있는 마커(`㉠`·`ⓐ`)를 그대로 포함하기 — 오히려 그대로 두는 것이 맞다

### 🔍 블록 — 형식은 자유, 내용은 자유가 아니다

> **🔍 해설 블록은 형식이 자유로울 뿐 내용이 자유로운 것이 아니다.
> 원문에 없는 사실을 지어내면 안 된다.
> 🔍 블록은 어떤 게이트도 보지 않으므로, 이 축의 유일한 방어선은 대표 표본 검수다.**

근거: `r20206d` Q40 — 게이트 5종을 전부 통과한 해설이 `ㄴ`·`ㄹ`을 **소포체·엽록체로 지어냈다.** 어느 게이트도 잡지 못했고, 대표 육안 검수에서만 드러났다.

## 2. 해설 생성·재작성 발주에 반드시 싣는다

새 해설을 만들거나 다시 쓸 때, 위 §1의 인용 규약 문구를 **프롬프트에 그대로 넣는다.** 넣지 않으면 모델이 📌 블록에 요약·설명 괄호를 넣는다(실측 — 2026-08 세션에서 반복 발생).

## 3. 결론줄

결론줄은 명사형으로 마감한다. 완결 문장(`~이다` / `~습니다`)을 쓰지 않는다.
근거: 공개 세트 결론줄 4,740건 중 명사형 계열 4,573건(96.5%).
자세한 것은 운용지침 §7-20.

## 4. 이 규약을 검사하는 도구

`pipeline/haesol_v2_gate.mjs` §2 인용 대조 축이 📌 블록만 검사한다.
**참고 도구다.** 출시를 막는 관문은 `quality_gate --scope=release` 하나뿐이다(운용지침 §7-23).
