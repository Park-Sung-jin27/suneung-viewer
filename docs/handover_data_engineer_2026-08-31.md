## 1. 이 자리가 하는 일

**지니쌤과 공부하자 / 짚이**(`www.jippi.kr`) — 수능 국어 기출 뷰어의 데이터를 책임진다.
핵심 상품성은 **선지 ↔ 지문 근거 1:1 형광펜**이다. 이게 조용히 죽으면 제품이 죽는다.

### 일하는 방식 — 발주·보고 루프

**품질 심사관**이 원본 시험지를 보고 판정해 발주(`D-nnn`)를 내리고, **대표**가 전달한다.
나는 **판정하지 않는다 — 후보까지만 낸다.** 원본을 볼 수 있는 쪽이 판정한다(S-01 · §13㉑).

**보고 형식** (매 응답 고정):

- 첫 줄: 진척 + `미push: N건 / 최근 배포 커밋: <해시> / 건드린 파일: <목록>`
- 본문: 결론 → 근거(수치 원문) → 자체 발견 결함 → 최대 리스크 → 다음 요청
- **「발주 항목 ↔ 실행 결과」 대조표 필수** (S-19). 미실행분은 **미실행이라고 쓴다.**
- 끝: **`지금 당장 할 것`(1~3개) / `하지 말 것`(1~2개) / `가장 큰 리스크`(1개)**
- 모든 판단에 `[Confirmed]` / `[Inference]` / `[Unverified]` / `[확인 필요]` 중 하나.
- 비전공자가 바로 실행할 수 있는 **짧은 한국어**로 쓴다.

## 2. 절대 규칙 — 어기면 사고가 난다

### 커밋·push

- **`git add <경로>` 한정. `git add .` / `-A` / `commit -a` 금지.** (공유 인덱스 혼입 2회 재발 실증)
- **데이터 수정과 도구 수정은 같은 커밋에 넣지 않는다.**
- push 는 **발주에 명시된 항목만**. 승인 전 push 금지.
- push 전 `git fetch origin` → ahead/behind → 필요시 **merge**(rebase 금지).
- 커밋 메시지에 `%` 를 쓰면 `printf` 가 자른다 → **heredoc(`-F-`) 사용.**

### 손대면 안 되는 것

| 대상 | 사유 |
|---|---|
| `src/` 전체 | 프론트 소관 (읽기는 허용·권장) |
| **`RELEASE_KEYS` · `RELEASED_KEYS` · `FREE_YEARS`** | 프론트 발주(F-xx) 사항 |
| `setId` 개명 | 영구 금지 |
| `all_data_204.json` 삭제·분할 | 금지 |
| 산출물 `public/data/free/` · `data-pro/` 커밋 | 금지 |
| `quality_gate` 에 축 추가 | §13⑱ |
| `quality_gate --fix` | 금지 |
| 해설(step3) 프롬프트·형식 임의 변경 | 기존 6,840개와 같은 틀 유지 |
| bracket 범위 자동 생성 | D-104 — 원본 PDF 판독으로만 |
| OCR 착수 | 별도 절차 승인 후에만 |
| 타 worktree 미커밋 파일 | 삭제·이동·복사 금지 |
| `.env` 커밋 / 키 값을 보고서·로그에 쓰기 | 금지 |
| 카드번호 입력 (테스트 카드 포함) | 금지 |

### 파일 쓰기

- **대용량 JSON 은 node `fs.writeFileSync` 만** (§13⑪). 셸 리다이렉션·PowerShell 파이프 금지 — BOM 이 섞인다.
- `annotations.json` 은 **2칸 들여쓰기 · 끝 개행 없음**. `JSON.stringify(ann, null, 2)` 로 쓴다.
  `JSON.stringify(ann)` 로 썼다가 6,142줄이 통째로 지워진 diff 를 낸 적 있다(D-154).
- `all_data_204.json` 은 **minified 한 줄**. `JSON.stringify(data)` (들여쓰기 없음).
- **Python heredoc 에서 `\n` 이 실제 개행이 된다** — 도구 SPEC 을 고칠 때 반복해서 터졌다.
  **`Edit` 도구를 쓴다.** 부득이 스크립트로 고치면 `node --check` 로 반드시 확인한다.

### 원문

- **원문 없이 텍스트·이미지를 만들지 않는다** (§13⑬). OCR·추출 결과를 원문으로 삼지 않는다.
- 본문 교정은 **전 텍스트 필드 전역 grep** — 반쪽 수리 금지 (§13⑭).
- **조용한 실패를 만들지 않는다** (§13⑳).

## 7. 내가 낸 사고 — 같은 실수를 반복하지 말 것

이 절이 이 문서에서 가장 값지다. **전부 내가 실제로 낸 사고다.**

### ① 덧붙이기 검산의 거짓 실패 — **두 번 당했다**

`from` 문구를 남기고 뒤에 덧붙이는 수정에서, 「`from` 이 사라졌는가」로 검산하면 **반드시 실패한다.**

- **D-168 ⑨**: 거짓 실패를 「안 써졌다」로 읽고 **재실행 → `<제1수> <제1수>` 중복 적용.**
- **D-180**: 라벨 「추가」 12건이 또 거짓 실패. 이번엔 **데이터를 먼저 확인**해 정확히 쓰였음을 보고, 백업 복원 → 검산 수정 → 재적용.

> **검산이 실패를 찍으면 데이터를 먼저 본다. 재실행은 원인을 확정한 뒤에만 한다.**
> 「교체」와 「추가」는 대조 방법이 달라야 한다(`d180_pat_domain_fix.mjs` 참고).

### ② 기존 산출물을 안 읽고 새로 판단했다 — **세 번**

| 사고 | 내용 |
|---|---|
| D-171 | `_pat_error` 에 `expected_domain: "R"` 이 **적혀 있었는데** 안 읽고 `pat` 을 L5 로 넣었다. 도메인부터 틀렸다 |
| D-172 | `quality_gate` 가 L3 를 안 잡는 것을 「구멍」이라 보고했는데, **코드 주석에 의도적 면제라고 적혀 있었다** |
| D-174 | 내가 만든 조사 도구의 범위(「`cs_ids` 가 빈 것만」)를 **보고할 때 빠뜨려** 「`pat=0` 1건」이라 했다. 실제로는 7건 |

> **S-15 그대로다. 판단하기 전에 코드·마커·기존 값을 읽는다.**
> **조사 수치를 보고할 때는 「무엇을 세지 않았는지」를 같이 적는다.**

### ③ `annotations.json` minify 사고 (D-154)

`JSON.stringify(ann)` 로 써서 6,142줄이 통째로 지워진 diff. 내용은 무손실이었다.
→ **`JSON.stringify(ann, null, 2)` + 끝 개행 없음.** 커밋 전 `git diff --stat` 으로 줄 수를 본다.

### ④ `evidence_assign` 의 `replace: true` 가 `cs_spans` 를 지울 뻔했다 (D-167)

`replace` 는 통째로 덮어쓴다. **기존 span 을 SPEC 에 그대로 옮겨 적어야 보존된다.**
dry-run 에서 사라지는 것을 보고 겨우 잡았다.

### ⑤ `--year` 가 세 도구에서 조용히 무시됐다 (D-156)

없는 회차에 「0건」이 떠 **통과한 것처럼 보였다.** → 회차 존재 가드 + 양성 회귀(S-16).

### ⑥ 발주 어구에 원문자가 빠져 있었다 (D-171)

데이터는 `서 있는 ⓓ 누각을` 인데 발주 어구엔 `ⓓ` 가 없었다.
→ **어구 대조는 2단계**: ① 원문 그대로 → ② 실패 시 **원문자·한자 괄호·공백 무시**.
②로 맞은 건은 보고에 🟡 로 남긴다. 조각이 **유일하게 특정될 때만** 확정한다.

### ⑦ 도구 파일에 NUL 바이트가 섞였다 (D-180)

git 이 binary 로 인식했다. 커밋 전에 제거했다. → **커밋 전 `node --check` + `git diff` 육안 확인.**

### ⑧ 심사관이 내 의견을 기각한 전례 (받아들일 것)

- **D-170**: 내가 L5 라 했으나 **L2 유지**. 근거 — ① `constants.js` 정의 ② 보기 문항 오답 `pat` 분포에 L2 도 32건 실재(「보기 문항 = L5」 불성립) ③ roadmap 202행.
- **D-163 ③**: 심사관 자신이 세운 전제(「`l20199e` 는 `cs_ids` 가 거의 비어 있다」)가 **실측 20선지 중 14개 보유**로 깨져 규칙을 폐기했다.

> **양쪽 다 실측이 이겼다.** 의견을 낼 때는 반드시 수치를 붙인다.
