## 배경

사용자가 SNS에서 발견한 멀티 에이전트 구조 — 비서 AI가 다른 직원 AI에게 작업 분배하는 형태. 우리 프로젝트(품질 심사관 → 데이터 엔지니어/프론트엔드 paste 형태)도 비슷한 흐름이라, 자동화 가능성 검토.

---

## 사용 가능한 도구

### 1. Claude Agent SDK (Anthropic 공식)

- 옛 이름: Claude Code SDK
- 공식 문서: https://docs.claude.com (검색: agent SDK)
- 장점: Anthropic 공식 → 안정성 + 모델 변경 따라가기 쉬움
- 단점: 비용 모니터링 도구가 아직 약함

### 2. CrewAI / LangGraph / AutoGen (오픈소스)

- CrewAI: 가장 간단, 역할 기반 (예: "품질 심사관" / "데이터 엔지니어")
- LangGraph: 복잡한 워크플로우 (조건 분기, 루프)
- AutoGen: Microsoft, 코드 생성 특화
- 장점: 무료, 커뮤니티 큼
- 단점: 모델 비종속(다른 LLM 섞을 수 있음) → 일관성 떨어질 수 있음

권고: Claude Agent SDK 우선. 모델/툴 일관성.

## 점진적 도입 로드맵 (권고안)

### Phase 1: 점검 자동화 (~~1~~2일 작업, 6개월 후)

- 매주 1회 자동 실행
- 출력: needs_human 큐 카운트 / legacy sentId telemetry / FAIL-FAST 분포
- 보고: 슬랙 또는 이메일
- 위험: 0 (읽기 전용)

### Phase 2: 추출 파이프라인 자동화 (~~3~~5일 작업)

- PDF 업로드 → Gemini 추출 → step3~6 → Gate 1 통과 시 라이브 반영
- 위험: 중 (Gate 1 신뢰도 검증 필요)
- 사람 검수: Gate 1 FAIL 시에만

### Phase 3: 품질 점검 자동화 (~1주 작업)

- LLM 기반 추가 검수 (cs_ids 정확성 등)
- needs_human 큐 자동 분류
- 위험: 높음 (LLM 판단 신뢰도)
- 사람 검수: 분류 결과 sample 검토

### Phase 4: 풀 자동화 (~1개월 작업)

- 비서 AI + 직원 AI 다수
- 사용자 = "오늘 5수능 완성해줘" 한 줄
- 위험: 매우 높음 (자가 검증 + 비용)
- 권고: 회기 1~10 종결 + 학생 1만명 도달 + 안정화 사후

## 자가 결함 방지 체크리스트 (자동화 도입 시)

자동화 구조에선 사용자 검증이 사라짐. 다음 안전장치 필수:

1. **자동 자가 결함 카운터**: 각 AI가 자기 출력 자가 검증 + 결함 발견 시 사용자 알림
2. **사용자 승인 게이트**: 라이브 데이터 변경 / $X 이상 비용 / 결함 N건 이상 누적 시 사용자 승인 의무
3. **롤백 자동화**: git tag + DB snapshot — 문제 발생 시 1번 명령어로 복구
4. **비용 일일 한도**: 자동화 비용 $X/day 초과 시 자동 정지
5. **사람 검수 sample 강제**: 자동 처리 100건 중 5건 무작위 사용자 알림 (핵심)

## 진입 사전 의무 사항

자동화 진입 시점이 오면 다음을 먼저 진행:

1. **회기 1~10 종결** — 시스템 결함 ↓ 사후 진입 (현재 결함 많은 상태에서 자동화 = 결함 곱셈)
2. **라이브 사용자 100명 이상** — 자동화 ROI가 사람 작업 비용 초과해야 의미 있음
3. **수익 모델 검증** — 자동화 비용 ($/month) 감당 가능 사실
4. **백업/롤백 인프라** — Supabase snapshot + git tag 자동화
5. **모니터링 도구** — 학생 신고 / 에러 추적 / 비용 추적 정합
