# 백로그 — 결제 안내를 alert 에서 인페이지 배너로 전환

> 등재: 2026-08-21 · 판정 출처: 대표 (F-27 취소 시 함께 판정)
> **결함 수정이 아니다.** 기능은 처음부터 정상이었다.

## 경위 — 기능은 정상이었다

F-27 은 "권한 부여 실패 시 화면에 아무 안내가 없다"는 전제로 발주됐으나,
대표 스크린샷으로 **문구가 실제로 떴다**는 것이 확인됐다(④ 테스트 orderId `…162203`):

> 결제는 완료됐습니다. 이용권 활성화에 문제가 있어 확인 중입니다…
> downfall121@gmail.com

원인은 코드가 아니라 **`alert` 창이 다른 창에 가려 늦게 인지된 것**이었다.
F-27 은 취소됐고, `src/App.jsx` 의 `ENTITLEMENT_FAILED` 분기는 그대로 둔다.

## 그래도 남는 개선점

`alert()` 는 결제 결과를 전하는 수단으로 약하다.

- **다른 창에 가린다** — 이번에 실제로 일어난 일이다.
- **닫으면 근거가 사라진다.** 사용자가 문의처 이메일을 적어둘 새가 없다.
- 브라우저·확장이 억제하면 아무것도 남지 않는다.
- 모바일에서 "이 페이지가 추가 대화상자를 만들지 못하게 함"이 켜지면 이후 알림이 전부 사라진다.

돈이 나간 자리의 안내는 **화면에 남아야** 한다.

## 설계안

`src/App.jsx` 의 결제 확인 effect(`paymentConfirmedRef` 가드 아래)에서 `alert()` 4곳을
상태로 바꾸고, `App` 의 `return (<Routes>…)` 을 감싸 배너를 함께 렌더한다.

```jsx
const [paymentNotice, setPaymentNotice] = useState(null); // {tone, title, body}
```

| 분기 | tone | 문구 |
|---|---|---|
| `code` 파라미터(결제창 닫기) | info | 결제가 취소됐습니다. 결제된 금액은 없습니다. |
| 세션 없음 | warn | 결제 확인을 위해 로그인이 필요합니다. 결제가 완료된 상태라면 로그인 후 자동으로 열립니다. |
| **`ENTITLEMENT_FAILED`** | warn | **결제는 완료됐습니다. 이용권 활성화에 문제가 있어 확인 중입니다.** + 고객센터 |
| 그 외 실패 | error | 결제 확인에 실패했습니다. |

**배너는 자동으로 사라지지 않게 한다.** 닫기 버튼만 둔다. 그것이 alert 대비 이득의
핵심이다.
