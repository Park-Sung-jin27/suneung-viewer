# 백로그 F-46 — `<보기>` 이미지 배치 분기 신설 + `bogiImage` 죽은 필드 정리

> 등재: 2026-08-31 · 판정 출처: 심사관 (D-182 ②)
> **출시 차단 아님.** D-179 로 도식이 화면에 뜨는 것은 확인 대상이고, 이 문서는
> **배치 순서와 죽은 필드**만 다룬다. 현 상태는 **수용 판정**이 났다.
> **착수는 9/3 이후.** 9/1~9/2 는 전면 동결이다.
> 데이터 담당은 `src/` 를 건드리지 않는다 — 아래는 전부 프론트 소관이다.

## ⓐ 세로 배치가 「텍스트 위, 이미지 아래」로 고정돼 있다

**위치:** `src/QuizPanel.jsx:680`

```jsx
// 기본: 세로 배치 (텍스트 위, 이미지 아래)
return wrap(
  <div style={{ display: "flex", flexDirection: "column", gap: "10px" }}>
    {textEl}
    <div style={{ textAlign: "center" }}>{imgEl}</div>
  </div>,
);
```

**문제:** 원본 시험지는 **도식이 위, 각주가 아래**다. 지금은 뒤집혀 나온다.

`2020_9월::r20209d` Q41 이 그 자리다. 지면에서는 `<보 기>` 상자 안에
도식(y 245~382pt)이 먼저 오고 각주(`* 각 원의 반지름은…`, y 394~470pt)가
그 아래에 붙는데, 화면에서는 각주가 먼저 뜨고 도식이 그 아래로 간다.

**⚠ 주석이 코드와 다르다 (S-15 실증).** 같은 파일 위쪽 주석은 이렇게 말한다:

```
//   imagePosition: 'right' | 'left' → 텍스트 옆 배치 (데스크탑)
//                  'top' | 'bottom' | undefined → 세로 배치
```

그런데 **`'top'` 을 처리하는 분기가 코드에 없다.** `right`/`left` 가 아니면
전부 같은 세로 분기로 떨어지고 순서는 항상 텍스트 먼저다. 데이터에
`imagePosition: "top"` 을 넣어도 **아무 일도 일어나지 않는다** — 실측 확인했다.

**수정안:** 세로 분기에서 `imagePosition === "top"` 이면 `imgEl` 을 먼저 그린다.
주석과 코드를 일치시키는 것이 핵심이다. 기본값(`undefined`)은 **지금 동작을
그대로 둔다** — LIVE 11문항이 그 배치로 이미 검수를 통과했다.

**데이터 쪽 후속:** 분기가 생긴 뒤에 `r20209d` Q41 에 `imagePosition: "top"` 을
넣는 것은 **별도 데이터 발주**로 받는다. 프론트가 먼저다.

## ⓑ `bogiImage` 가 아무 데서도 안 읽힌다

**위치:** 데이터에는 있고 `src/` 에는 소비처가 없다.

```
grep -rn "bogiImage" src/   →  0건
```

**문제:** `bogiImage: { url, alt }` 를 채워도 화면에 아무 영향이 없다.
실제로 그려지는 것은 `bogi.image` 뿐이다 (`QuizPanel.jsx:625` `resolveBogiImage`).

지금 이 필드를 가진 문항은 **2건**이다.

| 회차 | 세트 | 문항 | `bogi.image` | `bogiImage` |
|---|---|---|---|---|
| 2026수능 | `r2026c` | Q12 | 있음 (이게 그려진다) | 있음 (안 읽힘) |
| 2020_9월 | `r20209d` | Q41 | 있음 (이게 그려진다) | 있음 (안 읽힘) |

둘 다 `bogi.image` 가 같은 값을 갖고 있어서 **화면은 정상**이다. 문제는
「채우면 되는 필드」로 오해할 여지가 있다는 것이다. D-179 발주가 실제로
그렇게 읽혔다.

**수정안 — 둘 중 하나를 고른다. 섞지 않는다.**

1. **읽게 만든다** — `resolveBogiImage(bogi.image ?? bogiImage)` 로 폴백을 건다.
   `alt` 도 `bogiImage.alt` 까지 떨어뜨린다. 데이터는 안 고쳐도 된다.
2. **없앤다** — 데이터에서 `bogiImage` 를 지운다. 이건 **데이터 발주**가 되고
   `build_split` 의 `Q_FREE` 목록(`pipeline/build_split.mjs:57`)에서도 빼야 한다.

**권장은 1번이다** `[Inference]` — `Q_FREE` 가 이미 `bogiImage`·`bogiImages`·
`bogiType`·`bogiTable` 을 배분 대상으로 잡고 있어, 지우는 쪽은 건드릴 자리가 많다.

## 검증

- `imagePosition: "top"` 을 넣은 문항에서 **이미지가 텍스트보다 위**에 나오는가
- `imagePosition` 이 없는 LIVE 11문항의 배치가 **하나도 안 바뀌었는가** (회귀)
- `bogi.image` 가 없고 `bogiImage` 만 있는 문항을 만들어 **그림이 뜨는가**
  (1번 안을 택한 경우 — 실패 케이스로 뚫어 본 뒤 채택한다 · S-16)
- `r20209d` Q41 · `r2026c` Q12 를 gate3 로 육안 확인 (S-07 — 객체형 `bogi`)
